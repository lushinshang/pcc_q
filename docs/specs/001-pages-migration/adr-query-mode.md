# ADR-001：採用當日公告查詢

狀態：Accepted  
日期：2026-07-24

## 決策

使用政府採購網 `dateType=isNow` 與國防部機關代碼 `orgId=3.5`。UI 使用「當日公告」。

## 理由

產品名稱與已核准需求均指向當日標案。`isSpdt` 代表等標期內，會包含過去公告且與文案不一致。

## 後果

當日確實沒有公告時可能得到零筆。Production fetch 以零筆為異常 fail closed，避免空資料覆蓋上一版；若未來要支援合法零筆，需另立 ADR 並設計具來源證據的零筆驗證。

## 追記（2026-07-25）：機關不設限 + 30 天滾動累積

單次擷取查詢仍是 `dateType=isNow`（當日公告），**沒有改成日期區間查詢**，此決策不變。變動的是：

- `orgId` 由固定 `3.5`（國防部）改為空字串，改為擷取全國當日公告，於解析階段用機關名稱比對收斂進白名單（見 `src/contracts/orgWhitelist.ts`），前端提供機關下拉篩選（預設「國防部」）。
- Pages 端不再只保留當日單一批次，而是把每次成功擷取的白名單資料併入前一版資料，剪枝超過 30 天的舊記錄，形成滾動累積視窗；前端「當日／一週／一個月」是對這個累積視窗做本地端日期篩選，不觸發任何額外 PCC 請求。
- `TenderDataset.fetchedAt` 語意調整為「最近一次成功同步時間」，不是「每筆資料各自的擷取時間」。
- 排程從平日每小時改為平日每 3 小時（`0,3,6,9,12,15,18,21` 點 Asia/Taipei）。

此追記不推翻本 ADR 的核心決策（單次查詢仍是 isNow），只是把「顯示範圍」的責任從擷取端移到儲存端與前端。
