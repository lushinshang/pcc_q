## 1. 背景與問題陳述

政府電子採購網（PCC，`web.pcc.gov.tw`）是台灣政府標案公告的單一官方來源，但其網頁介面每次查詢僅能鎖定單一機關與短時間窗，且原始網站需要手動翻頁、無法依機關快速比較，也沒有可程式化訂閱的公開 API。對於需要每天掌握特定機關（如國防部）標案動態的使用者，人工瀏覽 PCC 網站查找、跨頁比對、判斷是否為新公告是重複且容易遺漏的工作。

本專案的前身是一個以 Google AI Studio 產生的原型（含 Express 後端、Gemini API、需要 API key），存在明確的安全與維運負擔（後端伺服器、API key 管理、生成式 AI 依賴皆非必要）。此次改造的產品目標是把它變成一個**免維運、免密鑰、資料可驗證**的公開儀表板。

## 2. 目標使用者

- **主要使用者**：需要每日掌握國防部（及未來可能擴充之其他中央/地方機關）標案公告的人員——例如採購承辦、投標廠商業務、政策研究者。
- **次要使用者**：對政府標案資料本身感興趣、想快速篩選特定機關/時間範圍標案的一般公眾。
- 使用情境為「查詢與瀏覽」，不含投標、下單、聯絡機關等交易行為——本站明確不是交易平台。

## 4. 範圍與非範圍

### 範圍內

- 不限機關逐頁擷取 PCC 標案公告（例行查詢當日；首次執行回填過去 30 天）。
- 前端本地端篩選：機關（白名單，含所有下轄單位）、日期範圍（當日／一週／一個月）、案名/案號關鍵字、招標方式。
- 30 天滾動資料視窗（自動剪枝超過 30 天的舊記錄）。
- 資料來源、同步頻率、機關白名單的公開說明面板。
- 自動化排程更新（平日每 3 小時）與人工觸發。

### 範圍外（明確排除）

- 使用者帳號、登入、個人化訂閱或通知（email/推播）。
- 標案投標、下單、聯絡窗口等交易行為。
- 非公開資料或需登入才能查詢的 PCC 內容。
- 生成式 AI 摘要／問答功能（前身原型曾用 Gemini，此版本刻意移除）。
- 自訂網域、CDN、反向代理等額外基礎設施（除非另行授權，見 [`threat-model.md`](../specs/001-pages-migration/threat-model.md) 殘餘風險段落）。
- 行動 App、瀏覽器擴充套件。

## 5. 產品原則

1. **零信任上游輸入**：PCC HTML 一律視為不受信任來源，任何進入發布資料的內容都要經過 schema 驗證。
2. **Fail closed 優先**：偵測到資料異常（結構漂移、同日新增驟減、拒絕比例過高）時停止發布，保留上一版，不讓錯誤資料上線。
3. **免密鑰、免後端**：不引入任何需要保管密鑰的元件；能用純靜態達成的功能不引入伺服器。
4. **可驗證優於可承諾**：任何「已完成」的宣稱都要有可重現的驗證證據（測試輸出、Live 驗收截圖/紀錄），不接受「應該沒問題」。
5. **公開資料，非官方整理**：頁面明確標示本站非官方，內容以 PCC 公告為準，避免使用者誤解為官方系統。

## 7. 假設與依賴

- PCC 網站（`web.pcc.gov.tw`）持續以現有 HTML 結構與查詢參數（`dateType=isNow`／`isDate`、分頁「下一頁」連結）對外開放，不需登入即可查詢任意機關。此為外部依賴，PCC 若改版介面會導致擷取失敗（設計上會 fail closed 並保留舊版，不會靜默發布壞資料）。
- GitHub Pages／Actions 服務持續可用；未啟用 branch protection（見 README CI/CD 段落），權限控管依賴 workflow 內部設計而非平台強制。
- 使用者以現代瀏覽器（支援 ES Module、`<details>` 原生互動）存取。

## 8. 已知限制

- 無使用者流量／行為分析（無後端、刻意不導入追蹤），第 3 節成功指標僅能以工程驗收數據代理。
- GitHub Pages 無法由 repository 自訂完整 HTTP response headers（HSTS、`X-Frame-Options`、`Permissions-Policy` 等不在控制範圍內），詳見 [`threat-model.md`](../specs/001-pages-migration/threat-model.md) 殘餘風險。
- 機關白名單為靜態列舉，新增機關需修改程式碼並重新部署，非使用者可自助設定。
- 排程頻率固定為平日每 3 小時，非即時（分鐘級）更新。

## 9. 路線圖（Now / Next / Later，非承諾期程）

- **Now**：本次系統文件補齊（PRD/SRS/STP/SDD）。
- **Next**（候選，未排入 sprint）：機關白名單擴充機制（例如改為設定檔驅動，減少每次新增機關的程式碼變更）；週末/例假日排程評估。
