# 系統文件索引（PM／系統分析視角）

本目錄提供產品／系統分析層級的正式文件，補齊 [`docs/specs/001-pages-migration/`](../specs/001-pages-migration/) 既有工程規格的產品層與正式結構缺口。**這兩個目錄不是互相替代關係**：

| 文件             | 目的                                                         | 權威範圍                                                                                                        |
| ---------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| [PRD.md](PRD.md) | 產品需求文件：背景、目標使用者、成功指標、範圍、Epic backlog | 產品／商業層決策的唯一權威來源                                                                                  |
| [SRS.md](SRS.md) | 軟體需求規格：外部介面、非功能需求、優先序                   | 結構性補充；逐條需求編號與驗收條件仍以 [`requirements.md`](../specs/001-pages-migration/requirements.md) 為權威 |
| [SDD.md](SDD.md) | 系統設計文件：情境圖、模組介面、資料設計、部署視圖           | 結構性補充；核心架構決策仍以 [`design.md`](../specs/001-pages-migration/design.md) 與 ADR 為權威                |
| [STP.md](STP.md) | 軟體測試計畫：策略、環境、進入/退出準則、風險分級            | 結構性補充；逐案測試 ID 對照仍以 [`traceability.md`](../specs/001-pages-migration/traceability.md) 為權威       |

## 更新原則

- 需求編號、驗收條件、測試案例 ID 的**內容本身**只改一個地方：`docs/specs/001-pages-migration/` 底下對應檔案。本目錄四份文件用連結引用，不重複貼原文，避免兩邊改一邊漏改。
- 產品層決策（範圍、優先序、成功指標）只改 `PRD.md`。
- 任何數字（測試數、coverage、URL、commit SHA）一律取當次實際執行輸出，不沿用舊快照；`STP.md` 第 7 節與 `README.md`（專案根目錄）的驗收表明確標註「快照」性質。
